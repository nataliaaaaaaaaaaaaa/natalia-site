# Сайт Натальи Пахомовой — инструкция по публикации

## Что в этой папке

```
natalia-site-publish/
├── index.html      ← сам сайт (открывается как главная страница)
├── 404.html        ← страница «не найдено» (GitHub Pages подхватит сам)
├── images/         ← все фото (21 файл, ~3 МБ)
├── video/          ← 2 видео для шапки сайта (~22 МБ)
├── favicon/        ← иконка сайта (вкладка браузера, значок на телефоне)
├── robots.txt      ← разрешение поисковикам индексировать сайт
├── sitemap.xml     ← карта сайта для поисковиков
└── README.md       ← этот файл
```

Всё, что нужно для сайта, лежит внутри этой одной папки. Ничего переносить из других мест не нужно — просто загрузите **всю папку целиком** на GitHub.

⚠️ **Важно:** раньше была проблема с тем, что часть фото/видео не отображалась. Причина — раньше файлы лежали отдельно от сайта. Теперь `index.html` ссылается на файлы по относительным путям (`images/...`, `video/...`), которые лежат прямо рядом с ним. Если при загрузке на GitHub вы сохраните структуру папок как есть (не переименовывая и не перекладывая файлы) — всё будет работать.

## Способ 1. Через сайт GitHub (без терминала) — самый простой

1. Зайдите на [github.com](https://github.com) и войдите (или зарегистрируйтесь).
2. Нажмите **New repository** (зелёная кнопка справа вверху или на github.com/new).
   - Repository name: например `natalia-pakhomova-site`
   - Оставьте репозиторий **Public**
   - Ничего из чекбоксов (README, .gitignore, license) не отмечайте
   - Нажмите **Create repository**
3. На странице нового репозитория нажмите **uploading an existing file** (или "Add file" → "Upload files").
4. Перетащите в окно браузера **содержимое** папки `natalia-site-publish` — то есть сам файл `index.html`, а также папки `images` и `video` целиком (их можно перетащить прямо как папки — GitHub сохранит структуру).
5. Внизу страницы в поле commit message можно написать `Первая публикация сайта`, затем нажмите **Commit changes**.
6. Дождитесь, пока все файлы загрузятся (видео ~19 МБ может грузиться дольше остальных — не закрывайте вкладку, пока не увидите зелёную галочку/список файлов).

Если браузер откажется загружать видео (изредка бывает с файлами больше ~20 МБ через веб-интерфейс) — используйте Способ 2 ниже, он надёжнее для видео.

## Способ 2. Через GitHub Desktop (надёжнее для видео, тоже без терминала)

1. Скачайте и установите [GitHub Desktop](https://desktop.github.com).
2. Войдите в свой аккаунт GitHub через приложение.
3. Создайте репозиторий так же, как в шаге 2 выше (можно прямо из GitHub Desktop: File → New Repository).
4. В качестве Local Path выберите папку `natalia-site-publish`.
5. Приложение покажет список изменённых/новых файлов — нажмите **Commit to main**, затем **Publish repository**.

## Включение GitHub Pages (чтобы сайт открывался по ссылке)

1. В репозитории на github.com откройте вкладку **Settings**.
2. В меню слева выберите **Pages**.
3. В разделе "Build and deployment" → Source выберите **Deploy from a branch**.
4. Branch: выберите **main**, папка — **/ (root)**, нажмите **Save**.
5. Подождите 1–2 минуты, обновите страницу — вверху появится ссылка вида:
   `https://ваш-логин.github.io/natalia-pakhomova-site/`

Это и есть публичный адрес сайта — им можно делиться с клиентами.

## Если после публикации что-то не отображается

- **Не загрузились фото/видео** → проверьте на GitHub, что папки `images` и `video` реально попали в репозиторий (откройте их на github.com — файлы должны быть видны). Если нет — догрузите их через "Add file" → "Upload files", выбрав именно эту папку с недостающими файлами.
- **Видео не проигрывается** — откройте `video/hair-restoration-scrub.mp4` на github.com напрямую и проверьте, что размер файла ~19 МБ (не 0 и не "Git LFS pointer"). Если GitHub предложит подключить Git LFS — не соглашайтесь, файл и так меньше лимита, лучше перезалить через Способ 2.
- Изменения на GitHub Pages могут применяться с задержкой 1–2 минуты — если правили файлы, подождите и обновите страницу (Ctrl/Cmd+Shift+R для сброса кэша).

## Если понадобится что-то поправить после публикации

Проще всего — через GitHub Desktop: открываете папку, вносите изменения в `index.html` (или добавляете новые фото в `images/`), в приложении нажимаете **Commit** → **Push origin**. Через 1–2 минуты изменения появятся на живом сайте.

## Фавикон (иконка сайта)

В папке `favicon/` уже лежит готовая иконка — тёмный квадрат с золотой буквой «N», в цветах сайта. Она подключена в `index.html` и `404.html` и покажется во вкладке браузера, в закладках и как значок при добавлении сайта на телефон. Ничего дополнительно настраивать не нужно — просто убедитесь, что папка `favicon/` тоже загрузилась на GitHub вместе со всеми остальными.

Если в будущем захотите заменить иконку на другую — замените файлы внутри `favicon/`, сохранив те же имена (`favicon.ico`, `favicon-16.png`, `favicon-32.png`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`).

## Страница 404

`404.html` — это страница, которую увидит человек, если перейдёт по неверной или устаревшей ссылке на сайт. GitHub Pages автоматически показывает файл `404.html` из корня репозитория для любого несуществующего адреса — никаких дополнительных настроек не требуется, файл просто должен лежать в репозитории рядом с `index.html`.

## SEO (продвижение в поисковиках)

Уже настроено внутри `index.html`:
- `<meta name="description">`, `<meta name="keywords">` — описание сайта для поисковой выдачи;
- Open Graph и Twitter-теги — красивое превью при отправке ссылки в мессенджерах и соцсетях;
- JSON-LD разметка типа `HairSalon` — помогает Google/Яндекс показывать сайт как карточку организации (адрес, телефон, вид услуг);
- `robots.txt` и `sitemap.xml` — разрешают и упрощают индексацию сайта поисковиками.

⚠️ **Важно сделать после того, как определитесь с доменом.** Сейчас в нескольких местах прописан условный адрес `https://pakhomova.ru/` — я поставила его как заглушку, потому что итоговый домен ещё не выбран. Если сайт останется на бесплатном адресе от GitHub (`https://ваш-логин.github.io/название-репозитория/`) или вы купите свой домен — замените `https://pakhomova.ru/` на реальный адрес в трёх местах:

1. `index.html` — строки `<link rel="canonical" ...>`, `<meta property="og:url" ...>`, `<meta property="og:image" ...>`, `<meta name="twitter:image" ...>` и внутри блока `<script type="application/ld+json">` (поле `"url"` и `"image"`).
2. `robots.txt` — строка `Sitemap: ...`.
3. `sitemap.xml` — строка `<loc>...</loc>`.

Если этого не сделать — сайт всё равно будет работать и открываться нормально, но превью в соцсетях и карточка в поиске будут ссылаться на несуществующий адрес `pakhomova.ru`. Если нужна помощь с заменой — просто пришлите мне финальный адрес сайта, и я поправлю все места сама.
